Parte 3

Se utiliza un LinkedHashMap para almacenar cada vértice junto con su lista de aristas salientes. 
Para guardar las aristas se utiliza ArrayList, mientras que para los conjuntos de vértices se utilizan LinkedHashSet y HashSet.
La implementación mediante listas de adyacencias consume O(V + E) de memoria, donde V es la cantidad de vértices y E la cantidad de aristas. 
Esto resulta conveniente cuando el grafo tiene pocas aristas en relación con la cantidad de vértices, ya que una matriz de adyacencias 
requiere O(V²) de memoria, independientemente de cuántas aristas existan realmente.
Las operaciones tienen distintos costos. Agregar un vértice cuesta O(1) en promedio, mientras que buscar un vértice cuesta O(V), 
porque se recorren las claves del mapa. Agregar una arista cuesta O(V + g), ya que primero se buscan los vértices y después se comprueba si la arista ya existe, recorriendo las aristas salientes del origen. Eliminar una arista también cuesta O(V + g). Eliminar un vértice cuesta O(V + E), porque hay que buscarlo, eliminarlo y recorrer las aristas restantes para quitar las que llegan a él.
Obtener el conjunto de vértices cuesta O(1), porque se devuelve una vista de las claves del mapa. 
Obtener todas las aristas cuesta O(V + E), porque se recorren las listas de adyacencias. 
Buscar una arista cuesta O(V + g), ya que primero se busca el vértice de origen y después se recorren sus aristas salientes.
Obtener las adyacencias de un vértice cuesta O(V), porque primero hay que localizarlo.
Obtener los sucesores cuesta O(V + g), porque se busca el vértice y se recorren sus aristas salientes. 
Obtener los predecesores cuesta O(V + E), porque se recorren las aristas de todos los vértices para encontrar cuáles llegan al vértice 
indicado. 
Vaciar el grafo tiene un costo O(1) para limpiar la estructura, sin contar el trabajo posterior del recolector de basura. 
La detección de ciclos mediante búsqueda en profundidad tiene un costo promedio O(V + E), porque cada vértice y cada arista se procesan 
como máximo una cantidad constante de veces.
También se podrían utilizar HashMap y HashSet en lugar de LinkedHashMap y LinkedHashSet. Estas estructuras ofrecen búsquedas promedio O(1), 
pero no conservan el orden de inserción. LinkedHashMap y LinkedHashSet mantienen ese orden, aunque consumen algo más de memoria.
Si se necesita consultar aristas con frecuencia, se podría almacenar cada conjunto de aristas salientes en un mapa por destino. 
De esta forma, se podría buscar una arista en tiempo promedio O(1) una vez localizado el vértice de origen, a cambio de consumir más memoria.
Por tanto, se considera adecuada la implementación mediante listas de adyacencias, ya que ofrece un buen equilibrio entre el consumo de 
memoria y el tiempo de ejecución. 
La elección de las colecciones depende de si se prioriza conservar el orden de inserción, reducir el consumo de memoria o 
acelerar las búsquedas de aristas.
